# Build an internal durable runtime and a complete coding product

The user chose equal emphasis on backend infrastructure and applied AI, with an internal custom runtime and a public coding service. Continumm will implement ownership, checkpoints, durable transitions and reconciliation itself while limiting workflow authoring to registered application code.

A mature orchestration engine would reduce implementation work but remove part of the chosen portfolio contribution. A general public workflow SDK would add a separate compatibility and developer-experience product. Both are deferred; the internal runtime and public coding journey have independent acceptance gates.
