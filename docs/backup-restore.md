# Portable export and restore check

`make export OWNER_ID=<account-uuid>` writes one encrypted account bundle under `~/.continuum/exports` by default. It reads a fixed allowlist of run tables and includes only unexpired, undeleted runs and committed artifacts that have an accepted-result reference. Every source archive is downloaded through the configured private object store and checked against its recorded archive and tree digests before packaging.

The package uses AES-256-GCM with a separate operator key supplied as `CONTINUUM_EXPORT_KEY` (64 hexadecimal characters or base64 encoding of 32 random bytes). Keep that key outside deployment and database settings; losing it makes exports unreadable. Export commands keep at most two live bundles, and each bundle expires at the earlier of seven days after creation or the earliest included content expiry. The database export journal stores only the export ID, account/run IDs, basename, hashes, and expiry. It never stores the key or package contents.

The export table allowlist is in [portable_exports.py](../src/continuum_api/portable_exports.py). It includes run history, task/model context, review evidence, effect metadata, and verified source archive references. Provider credentials, per-run keys, GitHub access tokens, browser sessions, OAuth state, deployment secrets, webhook bodies, and database connection strings are excluded. Account and run deletion or expiry receipts invalidate matching exports through a database trigger. `make export` first removes invalidated or expired local bundles; `make restore-check FILE=<bundle.cpx>` also destroys an invalidated bundle.

`make restore-check` authenticates the package, reads the current deletion journal before parsing the exported database rows or object payloads, filters deleted and expired runs, expires restored approvals, clears old execution ownership, and verifies all remaining source objects again. It materializes the filtered content only in a private temporary directory and removes that directory when checks finish. The result reports `quarantined_validated`, keeps mutations disabled, and identifies unresolved external operations for reconciliation. It does not import rows into a running application database or leave a second persistent content copy. If the current deletion journal cannot be read, it returns metadata-only status and exposes no run content.

This is a local recovery check, not an automatic production restore or zero-data-loss guarantee. Restored accounts must reauthorize, old sessions and reusable credentials never return, and unknown publication effects require operator reconciliation before any later write. The last successful export time and the possible loss window are recorded by running `make export`; record those values with the operator's recovery notes. Provider backups and logs remain subject to their providers' retention policies.
